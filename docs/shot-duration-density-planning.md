# 分镜时长与内容密度规划方案

## 背景

当前工作台从分集剧本到视频生成的后半段链路已经跑通：

```text
分集剧本
-> 分镜脚本
-> 分镜资产
-> Seedance 提示词包
-> 视频生成
```

但现有分镜生成逻辑存在一个明显问题：系统把分镜拆分规格固定为“6-10 个 15 秒分镜”。当用户提供的剧情很简单时，模型仍会为了满足数量和时长，把一个很小的剧情点拆成多个 15 秒片段，导致：

- 分镜数量过多。
- 单个视频内容单一。
- 多个分镜画面重复。
- 视频模型像是在强行凑满 15 秒。
- 产生大量无效镜头，增加视频生成成本。

反过来，如果只把分镜时长开放为 5-15 秒，又会出现另一个风险：模型可能把过多剧情塞进一个短片段，导致最终视频只执行前面高权重内容，后半段丢失。

因此优化目标不是简单改成“可变时长”，而是建立一套可落地的：

```text
剧情容量判断
-> 分镜数量规划
-> 单镜头内容预算
-> 动态时长分配
-> 后端校验
-> 提示词覆盖率校验
```

## 目标

1. 简单剧情不再强行拆成 6-10 个 15 秒片段。
2. 复杂剧情不被压进过短片段。
3. 每个分镜围绕一个戏剧意图，而不是一个孤立物理动作。
4. 分镜时长在 5-15 秒内动态分配。
5. 下游提示词包结构、提示词编辑交互、视频提交格式保持兼容。
6. 保持现有资产提取、Seedance 提示词编辑、Runway Bridge、APIMart API 流程不受影响。

## 现有问题复盘

### 当前硬约束

现有 `buildShotsPrompt()` 要求：

```text
把剧本拆成 6-10 个 15s 视频分镜
Each shot is one complete 15-second video segment
```

现有 `normalizeShots()` 会把每个分镜强制归一为：

```text
durationSec: 15
```

现有 `buildPromptPackagesPrompt()` 进一步要求：

```text
Each package represents one 15-second shot and must contain audio, dialogue, and 3-5 subShots.
For a 15s shot, prefer time ranges: 0.0-3.0, 3.0-7.0, 7.0-10.0, 10.0-15.0.
```

### 导致的问题

简单剧情会被迫扩展为：

```text
简单剧情
-> 6-10 个 15s 分镜
-> 每个分镜再拆 3-5 个 subShot
-> 每个视频请求都是 15s
```

当内容不足时，模型只能补充低信息量内容：

- 慢推镜头。
- 反复表情特写。
- 空镜和环境描述。
- 重复同一动作。
- 角色停顿和环顾。

这不是视频模型本身的问题，而是上游分镜规划给了它过空或过碎的输入。

## 核心原则

### 内容驱动规格

分镜规划应从“剧情内容量”出发，而不是从固定分镜数量出发。

```text
内容少 -> 分镜少、时长短
内容标准 -> 分镜适中、时长按节奏分配
内容多 -> 分镜多、但每个分镜仍只承载一个戏剧意图
```

### 一个分镜等于一个戏剧意图

一个分镜不等于一个动作。一个分镜应承载一个清晰的戏剧意图，并可以包含服务于该意图的连续动作链。

适合合并为一个分镜：

```text
主角走近龙蛋
-> 伸手触碰
-> 龙蛋发光
```

因为这三个动作都服务于同一个意图：主角第一次触发龙蛋。

适合拆成多个分镜：

```text
主角发现龙蛋
-> 怪物破门而入
-> 主角抓起龙蛋逃跑
```

因为这是三个剧情 beat：发现、危机出现、逃跑决策。

### 不为凑时长制造镜头

当剧情只够 30 秒，就不要扩展成 120 秒。

可以接受：

```text
3 个 8-10 秒分镜
```

而不是强行生成：

```text
8 个 15 秒分镜
```

## 分镜数量规划

建议将分镜数量从固定 `6-10` 改为动态范围。

| 剧情容量 | 典型内容 | 建议分镜数 |
| --- | --- | --- |
| 极简 | 只有一个动作目标或一个情绪点 | 1-3 |
| 简单 | 1-2 个剧情 beat | 3-5 |
| 标准 | 3-5 个剧情 beat | 5-8 |
| 复杂 | 多个场景/冲突/转折 | 8-10 |

分镜数量应同时参考：

- 分集目标时长。
- 用户输入剧情复杂度。
- AI 完善后的结构化剧本容量。
- 场景切换数量。
- 主要冲突数量。
- 角色行动目标变化。

## 分镜时长规划

Seedance 2.0 支持 5-15 秒片段，因此工作台可以继续使用现有 `durationSec` 字段，但不再固定为 15。

| 时长 | 适合内容 | 不适合内容 |
| --- | --- | --- |
| 5-7 秒 | 一个独立小 beat、一个明确画面变化、反应、转场、单个动作结果 | 多动作链、复杂台词、新角色完整出场 |
| 8-10 秒 | 一个标准 beat、1-2 个连续动作、1 句短台词 | 多场景切换、多个信息揭示 |
| 12-15 秒 | 一个完整微段落、2-4 个连续动作、1 个情绪转折、1-2 句短台词 | 多个剧情节点、多个目标变化 |

### 判断 3 个 5 秒还是 1 个 15 秒

判断标准不是平均分秒数，而是看这些动作是否属于同一戏剧意图。

使用 1 个 15 秒：

```text
同一场景
同一目标
一个情绪转折以内
一个核心信息揭示
动作连续且互为因果
```

拆成多个 5 秒：

```text
目标变化
场景切换
新威胁出现
新角色/关键资产成为画面重点
角色做出新的决策
每个动作都有独立结果
```

示例：

```text
1 个 15 秒：
主角靠近龙蛋 -> 伸手触碰 -> 龙蛋发光，主角震惊后退

3 个 5 秒：
主角发现龙蛋
怪物破门而入
主角抓起龙蛋逃跑
```

## 单分镜内容预算

每个分镜应有内容预算，防止过空或过满。

### 5-7 秒预算

- 1 个小 beat。
- 1 个主要动作或反应。
- 0-1 句极短台词。
- 1 个画面重点。
- 不建议场景切换。

### 8-10 秒预算

- 1 个标准 beat。
- 1-2 个连续动作。
- 0-1 句短台词。
- 1 个画面重点，最多 1 个辅助重点。
- 可以有轻微情绪变化。

### 12-15 秒预算

- 1 个完整微段落。
- 2-4 个连续动作。
- 0-1 个情绪转折。
- 1-2 句短台词。
- 可以有一个悬念、反应或信息钩子作为结尾。

## 分镜生成流程建议

### 第一阶段：剧情 beat 规划

分镜生成前，LLM 先输出内部规划，判断：

```text
本集有几个剧情 beat？
每个 beat 的复杂度是多少？
每个 beat 是否需要独立分镜？
哪些动作应该合并？
哪些动作必须拆开？
每个分镜建议时长是多少？
```

第一版可以把这个规划放在同一次 LLM 请求中，不一定新增前端 UI。

### 第二阶段：生成分镜脚本

根据规划生成分镜列表：

```json
{
  "shots": [
    {
      "id": "SH01",
      "order": 1,
      "durationSec": 10,
      "storyPurpose": "主角发现房间里的龙蛋异常发光",
      "shotType": "中景",
      "camera": "缓慢推近桌面上的龙蛋，再切到主角反应",
      "action": "主角推门进入房间，注意到桌上的龙蛋，靠近后发现蛋壳发出微弱紫光",
      "dialogue": "",
      "assetNotes": "主角、龙蛋、卧室",
      "visualNotes": "房间昏暗，龙蛋紫光是主要光源",
      "continuity": "承接主角进入卧室，结尾停在龙蛋发光和主角震惊反应"
    }
  ]
}
```

结构可以延续现有字段，不必一次性重构为复杂 JSON。

## 后端校验方案

后端校验由本地 Node 服务负责，位置建议在分镜归一化之后、写入 state 之前。

### 校验项

基础校验：

```text
durationSec 必须在 5-15 秒
action 不可为空
camera 不可为空
shot 数量不可超过 10
总时长不可明显超过分集目标时长
```

内容密度校验：

```text
5-7 秒分镜 actionSteps 不应超过 1-2 个
8-10 秒分镜 actionSteps 不应超过 2-3 个
12-15 秒分镜 actionSteps 不应超过 4 个
单分镜不应包含多个场景切换
单分镜不应包含多个核心信息揭示
单分镜不应包含过长台词
```

重复/过空校验：

```text
相邻分镜 action 高度相似时提示合并
相邻分镜 visualNotes 高度相似且没有剧情推进时提示合并
action 只有“看向”“停顿”“环顾”且无信息变化时判定过空
多个分镜都只描述同一反应时判定重复
```

### 处理策略

轻微问题：

```text
保存，但给 warning
```

中等问题：

```text
自动调整 durationSec
或标记为建议合并/拆分
```

严重问题：

```text
要求 LLM 局部重写
或拒绝写入本次结果
```

第一版可先实现：

```text
prompt 约束 + duration 归一化 + warning
```

后续再加自动重写。

## 提示词包生成适配

提示词包字段结构保持不变：

```json
{
  "shotId": "SH01",
  "durationSec": 10,
  "soundDesign": "...",
  "audio": [],
  "dialogue": [],
  "assetRefs": [],
  "subShots": [],
  "seedancePrompt": "..."
}
```

变化点只在生成规则：

- 不再写死“15 秒分镜”。
- 每个 package 按 `shot.durationSec` 生成。
- subShots 数量根据时长决定。
- timeRange 根据实际时长分配。

建议规则：

| durationSec | subShots 数量 |
| --- | --- |
| 5-7 | 2-3 |
| 8-12 | 3-4 |
| 13-15 | 4-5 |

示例：

```text
8 秒分镜：
0.0-2.0
2.0-5.0
5.0-8.0

15 秒分镜：
0.0-3.0
3.0-7.0
7.0-10.0
10.0-15.0
```

## 提示词覆盖率校验

为避免短片段塞入过多内容，提示词包生成后需要检查覆盖率。

示例：

```text
分镜 action:
主角推门进入房间，看到龙蛋发光，怪物破门，主角抱起龙蛋逃跑。

subShots:
0-3s 主角推门
3-6s 主角看到龙蛋
```

这种情况说明后半段“怪物破门、抱起龙蛋逃跑”丢失，应标记为覆盖不足。

第一版校验可以基于简单规则：

- 分镜 action 中的关键动词/名词是否出现在 subShots。
- 分镜 assetRefs 是否至少在一个 subShot 中出现。
- 分镜 dialogue 是否进入 dialogue 字段。
- subShots 的最后一段是否包含本分镜结尾落点。

不建议第一版做复杂语义判断，避免影响稳定性。

## 视频提交适配

视频提交格式不需要改变。

现有视频生成逻辑已经从：

```text
pack.durationSec || shot.durationSec || 15
```

读取时长，并通过 Seedance 的 `duration` 字段提交。只要上游正确写入 5-15 秒，APIMart Seedance 和 Runway Bridge 都可以继续使用当前字段。

需要确认：

- APIMart Seedance payload 的 `duration` 仍在 5-15 秒内。
- Runway Bridge 的 `providerSubmission.duration` 使用同一 duration。
- 前端展示不要再写死“15s”。

## 需要修改的模块

### 必改

`server.js`

- `buildShotsPrompt()`
  - 去掉固定“6-10 个 15s”。
  - 增加剧情容量、beat、动态时长、避免拆碎和避免塞满规则。

- `normalizeShots()`
  - 不再强制 `durationSec: 15`。
  - 接收模型返回的 `durationSec`。
  - 归一到 5-15 秒。

- `buildPromptPackagesPrompt()`
  - 不再要求每个 package 是固定 15 秒。
  - subShots 数量按 `durationSec` 变化。
  - timeRange 根据实际时长生成。

- `defaultSubShotRange()` 或新增函数
  - 支持按 `durationSec` 生成默认时间段。

### 建议修改

`public/app.js` / `public/index.html`

- 将“15s 分镜”文案改成“视频分镜”或“分镜片段”。
- 分镜卡片展示实际 `durationSec`。
- 生成按钮文案从“生成 15s 分镜”改为“生成分镜脚本”。

### 可后续增强

`server.js`

- 增加 `validateShotDensity()`。
- 增加 `validatePromptPackageCoverage()`。
- 增加 warning 字段供前端展示。

## 不应修改的模块

本次优化应避免影响以下稳定模块：

- 分镜提示词编辑器交互。
- inline asset chip 控件。
- 资产库管理。
- 分镜资产添加/删除引用。
- Seedance promptPackage 字段格式。
- APIMart Seedance API adapter。
- Runway Bridge 插件。
- 视频任务状态刷新。
- 提示词包导出结构。

## 兼容性策略

为了不破坏旧项目：

1. 旧分镜没有 `durationSec` 时，默认仍按 15 秒处理。
2. 旧提示词包没有新的 timeRange 结构时，前端照旧展示。
3. 用户已手动编辑的提示词包不自动重写。
4. 只有重新生成分镜/提示词包时才应用新规则。
5. 下游视频生成仍使用同样的 `prompt + image_urls + duration` 结构。

## 验收标准

### 简单剧情

输入：

```text
主角深夜进入卧室，发现桌上的龙蛋发光。
```

预期：

- 不应生成 6-10 个 15 秒分镜。
- 可生成 1-3 个 5-10 秒分镜。
- 不应出现大量环顾、停顿、重复特写。

### 标准剧情

输入：

```text
主角进入卧室，发现龙蛋发光，怪物破门，他抱起龙蛋逃跑。
```

预期：

- 可生成 3-5 个分镜。
- “发现龙蛋”和“怪物破门”应拆开。
- “靠近龙蛋并触发发光”可合并。

### 复杂剧情

输入包含多个场景和冲突：

- 分镜数可接近 8-10。
- 但每个分镜仍只承载一个戏剧意图。
- 不应把多个场景塞入一个短片段。

### 提示词包

- `durationSec` 与分镜一致。
- subShots 时间段覆盖完整 duration。
- 不丢失分镜结尾动作。
- 资产引用与原分镜一致。

### 视频请求

- APIMart Seedance 请求中的 `duration` 与分镜一致。
- Runway Bridge 提交的 duration 与分镜一致。
- 原有提示词编辑、资产 @、导出提示词包功能正常。

## 推荐实施顺序

1. 修改分镜生成 prompt，移除固定 6-10 个 15 秒硬约束。
2. 修改 `normalizeShots()`，允许 5-15 秒。
3. 修改提示词包 prompt，让 subShots 按实际时长生成。
4. 修改默认 timeRange 生成函数。
5. 调整前端文案，展示真实时长。
6. 增加轻量内容密度 warning。
7. 增加提示词覆盖率 warning。
8. 在简单、标准、复杂三类剧本上验收。

第一版建议做到第 1-5 步，先解决“强行拆碎和凑满 15 秒”的主要问题；第 6-7 步作为第二阶段增强。

## 第二阶段落地规则

本阶段解决“项目总剧本带有 2 分钟/时间轴，导致本集和分镜继续被固定成 15 秒模板”的问题。

### 分集容量

- `智能推荐` 不再直接继承项目总剧本里的 `2分钟`、`0:00-2:00`、`120秒` 等全项目时间标记。
- 若用户没有填写本集意图，系统按项目主线自动抽取一个聚焦本集，而不是把完整项目剧情塞入第一集。
- LLM 返回后，后端会按本集预算裁剪结构化场景数量，超出的场景转入 `deferredBeats`。
- `capacityNote` 统一改写为本集目标秒数、推荐分镜数量、保留/顺延的剧情范围，避免继续出现“6-10 个 15 秒分镜”的旧说法。

### 分镜时长

- 分镜生成仍先让 LLM 根据剧情输出 `durationSec`。
- 后端会检查总时长是否明显超过本集预算。
- 如果 LLM 返回大量 15 秒镜头且超出预算，后端会合并连续镜头，并按动作复杂度重新估算 5-15 秒时长。
- 合并只在同一批连续分镜内进行，不删除剧情内容；多个动作会写入同一个分镜的 action/visualNotes/continuity。

### 提示词包小片段

- 提示词包 schema 不再提供固定 `0.0-3.0` 示例，避免模型照抄。
- LLM 可以按动作权重输出非均分时间段。
- 后端会校验 `subShots.timeRange` 是否覆盖完整 `durationSec`、是否超过片段时长。
- 如果发现旧 15 秒模板，例如 `0.0-3.0 | 3.0-7.0 | 7.0-10.0 | 10.0-15.0`，后端会按动作权重重新分配时间段。

### 保持不变

- 不修改资产提取、资产库、提示词编辑器、`@资产` 控件。
- 不修改 Seedance/APIMart/Runway 的视频请求结构。
- 不自动覆盖用户已经手动编辑保存的提示词包；只有重新生成时应用新规则。
