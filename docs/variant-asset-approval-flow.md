# 变体资产确认与引用流程

## 目标

本功能把“连续性状态层”中的变体建议接入现有资产库，但保持用户可选：

```text
变体建议 -> 用户确认 -> 进入资产库 -> 生成/上传变体参考图 -> 分镜引用变体 -> 提示词包/视频请求使用变体参考图
```

默认流程不变。用户不点击“加入资产库”时，变体建议不会影响资产库、分镜引用、提示词包或视频生成。

## 数据关系

变体资产不是新的独立角色，而是挂在基础资产下的稳定外观形态。

示例：

```json
{
  "id": "CHAR01-V01",
  "type": "character",
  "name": "Benson 新手套装形态",
  "isVariant": true,
  "parentAssetId": "CHAR01",
  "variantOf": "CHAR01",
  "appliedAssetIds": ["PROP05"],
  "variantStatus": "draft",
  "sourceShotIds": ["SH01"]
}
```

含义：

- `CHAR01`：Benson 的基础身份资产。
- `PROP05`：新手套装装备资产。
- `CHAR01-V01`：Benson 穿上新手套装后的稳定外观变体。

## 前端交互

分镜制作页的连续性状态面板会显示“变体资产建议”。

用户点击“加入资产库”后：

1. 后端创建或复用对应变体资产。
2. 连续性状态中的候选会记录 `status: "accepted"` 和 `acceptedVariantId`。
3. 当前分镜的 `shot.assetRefs` 不会立即变化，已生成提示词包和视频也不会因为“入库”动作失效。
4. 用户可以到资产库中为变体资产上传图片或生成参考图。
5. 参考图准备好后，用户再点击“引用到本镜”，或在本分镜资产选择弹窗中选择该变体资产。

用户点击“引用到本镜”后：

1. 后端将当前分镜中的父资产引用替换为变体资产引用。
2. 如果是人物换装/装备类变体，后端会把该变体已经融合的 `appliedAssetIds` 从当前分镜参考中移除。例如 `CHAR01-V01 Benson 新手套装形态` 已经融合 `PROP05 新手套装`，引用变体后本镜默认不再单独提交 `PROP05`。
3. 当前分镜连续性状态写入 `activeVariantId`，并从该角色的 `wearing` 列表中移除已融合装备，避免后续继续把装备当独立穿戴资产提示。
4. 相关提示词包和视频标记为过期，需要重新生成或重新保存提示词。
5. 后续提示词包生成和视频请求只会从 `shot.assetRefs` 读取该变体资产，不会自动追加父资产或已融合装备资产。

## 生成/上传参考图

变体资产复用现有资产图能力：

- 可以手动上传变体参考图。
- 可以点击“生成参考图”。
- 生成时会根据变体类型选择参考来源：
  - 父资产参考图始终作为身份/主体锚点。
  - 人物换装/装备类变体走参考图编辑模式，父角色图作为身份最高优先级，应用装备图作为低优先级装备设计参考，同时把装备资产的文字描述提升为外观变化约束。
  - 非人物换装类变体可继续使用已应用装备/状态/场景资产参考图。
  - 项目风格主要通过文字风格约束继承；父资产图本身已经承载项目风格时，不再额外传项目风格图参与人物换装变体，避免参考图竞争。

例如生成 `Benson 新手套装形态` 时，会优先使用：

```text
Benson 基础角色图 = 身份最高优先级图片参考
新手套装图 = 只参考盔甲结构、颜色、材质、宝石、肩刺、护臂、腰甲、腿甲、靴甲等装备设计，不继承其中的人物身份
新手套装文字 = 外观变化约束（绿色头盔、银色护甲、肩刺、宝石胸甲，以及套装应有的完整穿戴区域）
项目风格 = 文字风格约束
```

变体资产生成采用强参考策略：

- 父资产必须已有参考图，否则变体图生成失败。
- 父资产的文字 prompt 不作为变体身份依据；如果父资产 prompt 与父资产图冲突，以父资产图为准。这一点对用户上传参考图尤其重要。
- 人物换装/装备类变体优先使用父角色参考图锁定身份，装备/服装资产图只作为装备设计参考；同时使用资产名称、别名、外观描述和 prompt 作为文字约束转移到父角色身上，避免把装备参考图中的另一个人物身份带入变体。
- 人物换装/装备类变体走生图模型的参考图编辑接口（`/images/edits`），而不是普通生成接口（`/images/generations`）。这样更接近用户手动在 Image2 工作台中“参考图编辑”的成功路径。
- 非人物换装类变体仍可使用已应用状态/道具/场景资产参考图；如果该类变体需要应用资产图但缺失参考图，则生成失败。
- 生图模型如果拒绝参考图字段，变体图不会降级为纯提示词生成，而是直接返回失败。
- 生成记录中的 `referenceImagePolicy` 会标记为 `required-for-variant`，用于确认本次生成是强参考模式。

人物换装类变体的稳定生成原则：

```text
父角色图 = 身份锚点
装备/服装图 = 装备设计参考，不继承人物身份
装备/服装描述 = 外观变化约束
请求方式 = 参考图编辑 / images edits
不要把“穿着装备的其他角色图”作为同权重身份参考图
```

这样做的原因是，许多装备资产图本身就是“另一个角色穿着装备”的参考图。如果把它与父角色图同权重提交，生图模型容易把第二张图的人脸、发色、肤色、身形也一起继承，导致变体不像原角色。当前流程会在 `/images/edits` 中把父角色图设为身份最高优先级，把装备图限定为设计参考，并把装备资产的 `name`、`aliases`、`look`、`function`、`prompt` 等内容提升到高权重提示词中。

人物换装类变体还需要区分“身份锁定”和“服装覆盖”：

- 身份锁定只保护脸、发型、发色、眼睛、肤色、头部轮廓、身体比例和角色识别点。
- 上衣、裤子、鞋子属于可被装备/服装覆盖的区域。若应用资产是套装、护甲套装、uniform、outfit、armor set 或 full gear，生成时必须按完整穿戴关系处理，包含头部、胸甲/上衣、肩部、手臂、腰部、腿部、膝/胫部和鞋靴。
- 只有应用资产明确是局部装备时，才允许未覆盖区域继续保留父角色原本衣物。
- 这样可以避免模型因为“保持父角色裤子/鞋子”而只生成头盔、胸甲和护臂，遗漏下装。

实际生成提示词应保持短而明确，接近用户在 Image2 中手动成功的路径：

```text
图1人物穿着图2装备，生成完整三视图。
图1保留人物身份。
图2只提供装备设计。
若图2是套装/护甲套装，必须完整覆盖上半身和下半身。
输出正面、侧面、背面三视图。
```

不要把资产库中的长篇剧情、变体原因、状态判断规则全部塞进生图提示词。那些内容用于流程判断和资产管理，不适合直接作为变体图生成主提示词。变体图生成阶段应让参考图承担主要信息，文字只做参考图角色分工、套装完整性、项目风格和输出格式约束。

## 避免与非变体资产冲突

核心规则：

1. 变体资产必须有 `parentAssetId`，不能作为全新角色身份存在。
2. “加入资产库”只创建候选变体，不改变当前分镜引用。
3. 当前分镜启用变体后，`shot.assetRefs` 中使用变体 ID，不再同时提交基础角色 ID。
4. 装备资产如果已经融入变体，默认不再作为本镜独立参考提交。例如角色已经是“穿新手套装形态”，就不再额外提交“新手套装”道具图。
5. 若镜头需要装备本身的独立特写、飞向角色自动拼装、摆在桌上、被拿在手里等明确独立出现的画面，可手动把装备资产重新加入该分镜引用。
6. 提示词包生成仍只使用当前 `shot.assetRefs`，因此最终视频请求不会同时收到“基础角色”和“角色变体”的冲突参考图，也不会默认收到已融合装备的重复参考图。

## 与现有流程的边界

现有稳定流程保持不变：

- 不生成连续性状态时，项目仍按“分镜脚本 -> 资产提取 -> 提示词包 -> 视频生成”运行。
- 不点击“加入资产库”时，变体建议只是提示，不会进入资产库。
- 不点击“引用到本镜”时，变体资产即使已入库，也不会影响当前分镜参考图。
- 不使用变体功能时，资产提取、提示词包生成、Seedance 视频请求、Runway 插件请求都继续按原有 `shot.assetRefs` 工作。
- 变体流程是独立的用户可选流程：只有“加入资产库”和“引用到本镜”这两个显式动作会改变分镜引用。
- 手动上传/生成变体图复用原资产库能力。
- 视频 API 请求仍只读取提示词包与 `shot.assetRefs` 对应的参考图。

## 验收建议

1. 在有变体建议的分镜点击“加入资产库”，确认资产库出现 `变体 · 父资产ID` 标记。
2. 此时检查当前分镜资产列表，不应自动替换为变体。
3. 为变体资产上传或生成参考图。
4. 回到该分镜点击“引用到本镜”，确认本分镜参考资产从父资产替换为变体资产。
5. 若变体融合了装备/服装资产，确认该装备/服装资产默认从本镜参考列表和提示词包引用中移除。
6. 如果镜头确实需要装备独立出现，可手动通过“+”把装备重新加入本镜参考。
7. 重新生成或保存该分镜提示词包，确认提示词包引用的是变体资产。
8. 不需要调用视频模型即可完成以上验收。

## 回滚方式

如需撤销本功能：

1. 删除 `/api/assets/variants/accept`、`/api/assets/variants/apply-to-shot` 路由与相关函数。
2. 回退前端变体建议中的“加入资产库”按钮和调用逻辑。
3. 回退变体资产图生成时附加父资产/装备参考图的逻辑。
4. 已创建的变体资产可以保留为普通资产，也可以手动删除；旧流程会继续按 `shot.assetRefs` 工作。
