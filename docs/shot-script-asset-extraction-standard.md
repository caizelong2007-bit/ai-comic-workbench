# 分镜脚本生成与资产提取标准

## 背景

当前工作台已经跑通从分集剧本到 15s 分镜、资产提取、Seedance 提示词包和视频片段生成的主流程。后续需要优化两个稳定性问题：

- 分集剧本拆成 6-10 个 15s 分镜时，需要控制每个分镜的内容量，避免单镜头过满或过空。
- 资产从分镜脚本中提取时，需要避免资产身份污染，例如“纸箱”被合并到“银色收银铃”这类问题。

本标准用于定义后续分镜脚本生成、前端可视化编辑、资产提取和后端校验的统一规则。

## 目标

分镜制作模块需要同时满足三类需求：

1. 人类可读：前端展示应接近导演分镜稿，而不是直接展示 JSON。
2. 用户可编辑：用户可以像编辑提示词模块一样，修改镜头、动作、台词和关键元素。
3. 系统可校验：后端保存结构化数据，并在保存、提取资产、生成提示词前做规则校验。

核心原则：

```text
用户看到的内容 = 后端保存的内容 = 后续资产提取和提示词生成使用的内容
```

## 推荐流程

```text
分集剧本
  -> LLM 提取剧情节拍
  -> 后端校验节拍数量与内容量
  -> LLM 生成 6-10 个 15s 分镜脚本
  -> 后端校验每个分镜内容量
  -> 前端以导演稿卡片展示并支持编辑
  -> LLM 从分镜中提取候选资产
  -> 后端匹配项目资产库
  -> 后端做资产身份一致性校验
  -> 写入 shot.assetRefs
  -> 生成 Seedance 提示词包
```

LLM 负责提出建议，后端负责验收、修正、拒绝或要求局部重试。

## 前端展示标准

前端不直接展示完整 JSON，而是渲染为分镜导演稿卡片。

推荐展示格式：

```text
[15s] 雨夜街角｜建立林舟失业后的狼狈状态

[运镜]
雨滴近景拉焦到街角远景，手持跟随林舟奔跑，最后上摇到便利店招牌。

[画面动作]
林舟抱着纸箱冲入画面，差点滑倒后停在街角喘息。

[动作步骤]
1. 林舟从雨中冲入画面
2. 纸箱里的私人物品晃动散落
3. 他停在街角抬头看到便利店招牌

[台词/旁白]
旁白：有些门，不是为了让你躲雨才打开的。

[关键元素]
角色：林舟
场景：异世界便利店外街角
关键道具：便利店霓虹招牌
临时道具：被雨水泡软的纸箱

[连续性]
林舟尚未进入便利店，纸箱始终抱在怀里。

[衔接状态]
承接上一镜：林舟在雨夜街角，抱着纸箱，刚被辞退后的狼狈状态仍在。
进入下一镜：便利店门自动打开，下一镜从林舟警惕地进入便利店开始。
```

## 前端编辑标准

建议优先采用“卡片预览 + 字段化编辑”：

- 卡片模式：类似参考平台的自然语言分镜稿，适合快速浏览。
- 编辑模式：字段化编辑镜头、动作、台词、关键元素、连续性。
- 保存后：前端组装结构化 shot JSON，提交给后端。

后续如果需要更自然的写作体验，可以扩展为类似提示词模块的 inline asset chip 编辑器：

- 用户输入 `@` 选择项目资产。
- 资产以 chip 形式嵌入句子。
- 删除 chip 等同于删除资产引用。
- 保存时以可见编辑内容为准。

不论采用哪种编辑方式，都必须保证：

```text
前端可见内容保存后不会被旧字段恢复
后续资产提取使用保存后的最新内容
后续提示词生成使用保存后的最新内容
```

## 分镜内容量校验

每个 15s 分镜建议满足：

- 1 个主要戏剧意图，而不是 1 个孤立物理动作。
- 1 个主场景。
- 2-4 个围绕同一戏剧意图的连续动作步骤。
- 0-1 个情绪转折。
- 1-2 句台词或旁白。
- 不承担多个剧情节点。
- 结尾有一个动作落点、反应、悬念或信息钩子。

这里的“一个主要戏剧意图”可以包含一条完整动作链。例如：

```text
主要戏剧意图：林舟发现便利店入口。
动作链：
1. 林舟抱着纸箱冲进雨夜街角。
2. 他差点滑倒，纸箱里的东西晃动散落。
3. 他停下喘息，抬头看到霓虹招牌。
4. 招牌闪烁，便利店门自动打开。
```

这可以作为一个 15s 分镜，因为所有动作都服务于同一个意图：发现入口。

内容过多示例：

```text
主角冲进便利店、发现没人、听到收银铃说话、黑斗篷人进门、购买糖、主角拒绝、规则启动。
```

这应拆成多个 15s 分镜。

内容过少示例：

```text
主角看着门。
```

如果没有情绪变化、画面推进、声音信息或悬念，应与相邻节拍合并或补充动作。

不推荐按孤立动作硬切：

```text
SH01 林舟冲进街角。
SH02 林舟差点滑倒。
SH03 林舟抬头看招牌。
```

推荐按戏剧意图合并：

```text
SH01 林舟在雨夜街角狼狈奔跑，差点滑倒后抬头发现便利店招牌。
```

这样可以避免画面单一、节奏拖沓，也避免把可以在 15s 内表述清楚的连续动作拆成多个 15s 分镜。

## 分镜连续性标准

资产解决的是“一致性”，例如角色、场景、道具长得一致。连续性解决的是“前后发生关系是否接得上”，不能只靠资产图解决。

同一集内的分镜连续性至少包含：

- 空间连续性：角色从哪里到哪里，场景切换是否有过渡。
- 时间连续性：上一镜结束后，下一镜是否自然发生。
- 动作连续性：上一镜的动作落点，是否成为下一镜的起点。
- 情绪连续性：角色情绪是否有递进，而不是无因跳变。
- 道具状态连续性：道具在谁手里、在哪里、是否被使用或放下。
- 信息连续性：观众已经知道什么，下一镜不能重复或跳过关键解释。
- 冲突连续性：危机是否逐步升级，而不是无因无果。

建议每个分镜保存三类连续性字段：

```text
continuityIn：本镜头开始时的状态。
continuityOut：本镜头结束时的状态。
transitionToNext：下一镜应如何承接本镜头。
```

前端展示时不需要暴露完整 JSON，可以展示为：

```text
[衔接状态]
承接上一镜：林舟在便利店门外，门自动打开，仍抱着纸箱。
进入下一镜：从林舟推门进入便利店开始。
```

后端可按相邻分镜做规则校验：

```text
SH01.continuityOut.location 应能接到 SH02.continuityIn.location。
SH01.continuityOut.characterStates 应能接到 SH02.continuityIn.characterStates。
SH01.continuityOut.openQuestions 应在后续分镜中被保留、推进或解答。
```

连续性异常示例：

```text
位置跳变：
SH01 out: 林舟在便利店门外。
SH02 in: 林舟站在收银台后。
中间没有“进入便利店”的动作。
=> continuity warning

道具丢失：
SH01 out: 林舟抱着纸箱。
SH02 in: 林舟空手。
中间没有放下纸箱动作。
=> continuity warning

情绪跳变：
SH01 out: 疑惑、警惕。
SH02 in: 愤怒、崩溃。
中间没有触发事件。
=> continuity warning
```

处理策略：

- 轻微问题：保存并在前端显示连续性提示。
- 中等问题：要求用户确认或编辑承接描述。
- 严重问题：要求 LLM 局部重写下一镜的开头或重写相邻分镜的过渡。

## 后端校验职责

这里的后端指本地 Node 服务 `server.js`。

后端不只是转发 LLM 结果，而应该在写入 `data/state.json` 前进行固定规则校验。

分镜校验示例：

```text
durationSec 必须为 15
actionStepCount 建议 <= 3
dialogueLineCount 建议 <= 2
sceneCount 建议 = 1
emotionTurnCount 建议 <= 1
mainAction 不可为空
camera 不可为空
```

处理策略：

- 轻微问题：后端补默认值或标记 warning。
- 中等问题：保存但前端显示“内容偏多/偏少”。
- 严重问题：拒绝保存，或只要求 LLM 局部重写该分镜。

## 资产提取标准

资产提取的目标是为当前分镜选择对画面一致性有影响的参考对象，而不是把所有名词都变成资产。

应提取：

- 说话或行动的主角。
- 影响动作的配角或生物。
- 当前镜头的主场景。
- 被持有、操作、触发剧情或反复出现的关键道具。
- 已有参考图且本镜头明确出现的资产。

不应提取：

- 雨夜、霓虹、烟雾、积水、光效、速度线。
- 情绪、氛围、镜头运动、字幕、音效。
- 一次性背景杂物。
- 没有稳定外观要求的临时小物件。

临时道具处理：

- 只用于表现状态的物件可以写入 `visibleElements.props`，但标记为 `temporary`。
- `temporary` 默认不进入资产库，除非它后续反复出现或成为剧情关键物。

## 资产匹配与合并标准

资产提取时，LLM 可以建议复用或新建资产，但最终合并由后端判断。

匹配依据：

- 类型一致：character / location / prop 必须一致。
- 名称或别名命中。
- 角色身份一致。
- 道具功能一致。
- 外观描述一致。
- 已有参考图可增强复用优先级。
- 多分镜复用可增强重要性。

禁止合并条件：

- 类型不同。
- 名称相似但功能冲突。
- 外观明显冲突。
- 一个资产已有参考图，incoming 描述会破坏该参考图身份。
- 道具类仅因模型复用了同一 id，但名称、功能、外观不一致。

示例：

```text
existing: 银色收银铃
incoming: 被雨水泡软的纸箱
```

即使模型输出同一个 `PROP02`，后端也应判定为冲突，不允许合并。处理方式可以是：

- 如果纸箱只是临时物，不创建资产。
- 如果纸箱后续反复出现，则创建新的 `PROPxx`。

## 资产引用数量

当前 Seedance 2.0 可支持更多参考图，但工作台仍应控制每镜参考资产数量，避免为了数量而牺牲一致性。

当前建议：

- 每个分镜最多 6 个参考资产。
- 优先级：主角 > 主场景 > 关键配角/生物 > 关键道具 > 已有参考图资产 > 多分镜复用资产。
- 如果超过上限，删除临时道具、背景物、低影响道具和无参考图资产。

## 与提示词模块的关系

分镜脚本不是直接给 Seedance 的最终 prompt。

关系如下：

```text
分镜脚本
  -> 提取资产
  -> 资产参考图
  -> Seedance 提示词包
  -> 视频请求 prompt + image_urls
```

分镜脚本更新后，应标记下游内容可能过期：

- 已提取资产需要重新确认。
- 已生成 Seedance 提示词包需要提示重新生成。
- 已生成视频需要标记 stale。

## 验收标准

后续实现该需求时，至少需要验证：

- LLM 生成的分镜数量稳定在 6-10 个。
- 单个 15s 分镜不会承载多个剧情节点。
- 单个 15s 分镜不会被误拆成“一个孤立动作一镜”，而是围绕一个戏剧意图组织连续动作链。
- 相邻分镜具备可追踪的 continuityIn、continuityOut 和 transitionToNext。
- 前端能提示位置跳变、道具丢失、情绪无因跳变等连续性问题。
- 前端显示为人类可读分镜卡片，而不是裸 JSON。
- 用户编辑分镜后，刷新页面仍保留修改。
- 编辑后的分镜用于后续资产提取。
- 临时元素不会默认进入资产库。
- 纸箱、手机、收银铃这类不同道具不会被合并成同一个资产。
- 每个分镜最终 assetRefs 不超过配置上限。
- 分镜修改后，下游提示词包和视频会被标记为需要更新。

## 当前实现待优化点

现有实现已经具备基础能力：

- `server.js` 可调用 LLM 生成分镜。
- `server.js` 可从分镜提取资产并合并到项目资产库。
- 前端可触发单镜头资产提取和提示词生成。
- 提示词模块已支持 inline asset chip 编辑，可作为后续分镜编辑体验的参考。

待优化点：

- 分镜生成前缺少剧情节拍层。
- 分镜脚本结构仍偏自然语言字段，内容量校验不够明确。
- 分镜之间缺少显式连续性状态链。
- 前端分镜卡片可读性和编辑性还不够。
- 资产合并需要增加身份一致性校验，防止资产污染。
- 分镜变更后需要更明确地标记资产、提示词包和视频的 stale 状态。
