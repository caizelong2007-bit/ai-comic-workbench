# v1.9 Release Notes

## Summary

v1.9 adds an optional continuity-state and variant-asset workflow for short drama production. The existing main pipeline remains unchanged when this workflow is not used.

## Added

- Continuity state layer for shots:
  - Records shot-to-shot continuity such as character state, worn equipment, held props, location hierarchy, damage state, and relationship progress.
  - Supports generation, manual review, and manual editing.
- Variant asset workflow:
  - Users can accept a variant suggestion into the asset library.
  - Users can generate or upload a variant reference image.
  - Users can explicitly apply a variant asset to a shot.
- Character equipment variant generation:
  - Uses image edit mode with parent character image as identity reference.
  - Uses applied equipment image as design reference.
  - Keeps prompts short and explicit to match Image2's stable reference-edit workflow.
- Variant reference conflict handling:
  - Applying a character-equipment variant replaces the parent character reference in the shot.
  - Equipment already fused into the variant is removed from the shot reference list by default.
  - Prompt packages and video records are marked stale after variant application.

## Changed

- Asset extraction and prompt package generation can read continuity states when they exist.
- If no continuity states exist, the original script -> shot -> asset -> prompt -> video flow behaves as before.
- Variant image generation does not fall back to prompt-only generation when required references are missing.

## Rollback Notes

The feature is isolated behind explicit user actions:

1. Do not generate continuity states if the legacy flow is desired.
2. Do not accept/apply variant assets if shot references should remain unchanged.
3. To remove the feature later, revert the continuity routes, variant routes, frontend continuity/variant UI, and variant image-edit helpers.
