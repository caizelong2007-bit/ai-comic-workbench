# v1.7 Release Notes

Release date: 2026-06-11

## Version goal

v1.7 adds Runway Bridge as an optional browser automation extension for video generation. It is a temporary cost-saving path for submitting existing Seedance prompt packages to the Runway web UI, while keeping the original APIMart Seedance API flow available and unchanged.

This version is intentionally plugin-like: selecting `runway-bridge` creates local bridge tasks, and selecting `apimart-seedance` still uses the direct API adapter.

## Key updates

### Runway Bridge provider

- Added `runway-bridge` as a video provider option in the model settings.
- Added a default platform video model named `Runway Bridge Seedance 2.0`.
- Added a local bridge queue so workbench video submissions can wait for the browser worker.
- Added explicit Runway task statuses in the UI: waiting for Bridge Worker, processing, submitted to Runway, failed, and external.
- Added Runway-specific status help text so the UI does not look like silent infinite loading.

### Browser bridge worker

- Added `tools/runway-bridge`, a separate Node package that controls the logged-in Runway web UI through Chrome remote debugging.
- The bridge claims one workbench task at a time and waits when Runway already has two active generations.
- The bridge uploads selected reference images with semantic temporary names and fills a Runway-specific compact prompt.
- The bridge submits tasks to Runway and reports progress, failure, or external submission back to the workbench.
- Runtime logs and temporary upload files are ignored by Git.

### Provider-specific prompt package

- The canonical Seedance prompt package and APIMart request payload remain unchanged.
- Runway receives a derived `providerSubmission` package only when the selected provider is `runway-bridge`.
- The derived Runway prompt includes an image-number and `@asset` map to reduce reference confusion in the browser-only workflow.
- The derived Runway prompt is capped for the Runway web UI and does not overwrite the saved prompt package.

### Launcher

- Added `start-workbench-runway.bat` to start the normal workbench and the Runway Bridge worker together.
- Normal startup through `start-workbench.bat` remains available for the direct API workflow.

## Existing API flow audit

The APIMart Seedance flow was checked before this release:

- `apimart-seedance` still enters `callApimartSeedanceVideo()`.
- `runway-bridge` is gated by `isRunwayBridgeAdapter(adapter)` and creates local bridge tasks instead of calling the video API.
- Reference images for APIMart still go through `ensureApimartImageUrl()` and `uploadImageToApimart()` when needed.
- Reference images for Runway are marked as `local-upload` and are consumed only by the bridge worker.
- Video status refresh continues to call the APIMart task status API for normal API tasks.
- Runway-specific UI labels are shown only for videos identified by `provider/source/kind/bridge.provider = runway-bridge`.

## How to remove Runway Bridge later

Short-term removal:

1. Stop selecting `runway-bridge` in model settings.
2. Select the normal `apimart-seedance` video model.
3. Stop the Bridge Worker terminal.
4. Keep using the normal workbench start command.

Permanent cleanup:

1. Delete `tools/runway-bridge`.
2. Delete `start-workbench-runway.bat`.
3. Remove the `runway-bridge` provider option from `public/index.html`.
4. Remove Runway Bridge status helpers and labels from `public/app.js`.
5. Remove `.runway-status` styles from `public/styles.css`.
6. Remove `RUNWAY_BRIDGE_*` constants, `defaultRunwayBridgeConfig()`, bridge routes, queue helpers, provider submission builders, and `isRunwayBridgeAdapter()` branches from `server.js`.
7. Remove Runway Bridge temp ignore entries from `.gitignore`.

The direct APIMart Seedance API flow does not depend on `tools/runway-bridge`, so deleting the bridge folder alone will not break API-key video generation as long as projects use the APIMart video provider.

## Rollback

To inspect v1.6:

```powershell
git checkout v1.6
```

To create a maintenance branch from v1.6:

```powershell
git switch -c release/v1.6 v1.6
```

To revert v1.7 on a branch:

```powershell
git revert <v1.7-merge-commit>
```
